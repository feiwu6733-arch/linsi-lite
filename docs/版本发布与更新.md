# GitHub 版本发布与更新

固定仓库：https://github.com/feiwu6733-arch/linsi-lite

用户启动灵思后会自动检查正式 Release，持续运行时每 24 小时再检查一次。设置页提供手动检查、下载更新、更新并重启；用户可以稍后提醒或忽略某个版本。没有网络不会阻止本地使用。检查只请求公开版本公告，不发送账号、作品、报告或 API Key。

GitHub 匿名接口限流或连接失败时，会改读同一仓库最新 Release 附带的 update.json 公告，无需配置 GitHub 令牌。公告与 ZIP、校验文件由同一次发布生成，下载后仍校验文件摘要和包内清单。

## 发布新版

1. 修改代码，更新 `linsi/__init__.py` 的 VERSION（例如从 0.6.0 改为 0.6.1），同步 README 与 RELEASE_NOTES.md。
2. 将公开发行文件提交到 main。
3. GitHub Actions 自动测试并按 release-files.json 打包；通过后创建对应版本的 GitHub Release，附带 ZIP 和 SHA-256 文件。同一版本已发布时不会覆盖。
4. 已安装更新功能的用户下次检查就会收到通知。

只上传发行清单内的文件。不要上传 .local、登录配置、API 密钥、本机测试记录或个人更新脚本。发布流程需要仓库 GitHub Actions 的 contents: write 权限，使用 GitHub 自动签发的运行期令牌，不需要给用户配置令牌。

## 用户更新

GitHub Release 必须是正式版，名称为 vX.Y.Z，附件为 linsi-lite-X.Y.Z.zip。客户端只接受此仓库的 HTTPS 下载地址、GitHub 返回的 SHA-256 摘要、符合 update_format=1 的包内 MANIFEST.json 和发行清单。预发布版、缺少校验摘要、文件损坏或路径不合法的包不会自动安装。

用户点击“备份并更新”后，会先检查所有工作台没有进行中的任务，再关闭当前服务。独立安装器等待这个进程退出，备份将被替换的发行文件和数据库，保留业务目录、浏览器登录、API 配置与本地模型。安装后启动服务，检查新进程的版本和健康状态；启动失败则还原文件和数据库并恢复旧版。

安装器和备份保存在当前数据目录的 updates 子目录。自定义 Python 依赖变更、跨平台更新等不应直接复用此包格式；先验证兼容性并在更新说明中写清要求。当前一键安装支持 Windows，其他平台可查看发布历史手动下载。

0.5.1 及更早版本没有更新检查器，需要先安装一次 0.6.0，之后才能自动收到后续提醒。
